# デザイントークン定義スキル

このスキルは、プロジェクトルートの `DESIGN.md` を作成・更新するためのガイドです。
`DESIGN.md` は**全画面のデザインの単一の正**であり、UI実装は必ずこれに従います。

## 背景（なぜ必要か）

AIが生成するUIは、指示が無いと学習データの統計的平均（Inter・紫グラデーション・3枚カード等）に収束し、「AIが作った」と分かる見た目になります（分布収束）。
対策は (1) 方向性を1つ強制選択し (2) トークンを固定し (3) AIの既定値をブラックリストで封じること。このスキルはその3つを `DESIGN.md` として固定します。

## 既存ドキュメントの優先順位

1. **既存の `DESIGN.md`** — 最優先。既にあれば構造と決定を維持しながら更新する
2. **このスキルのガイドと `template.md`** — 新規作成時に使用

## 前提条件

- `docs/product-requirements.md`（PRD）を読み、対象ユーザー・用途・トーン（信頼感/遊び/高級感/実用）を把握していること
- ユーザー（開発者本人）がグローバルに `design-director` エージェントを持つ場合は、方向性選択と実装をそのエージェントに委任してよい。無い場合は本ガイドに従う

## 手順

### 1. 方向性を1つだけ選ぶ（最重要）

プロダクトの性格に合うものを1つ選び、選定理由を一言で書く。
**収束禁止**: 迷ったときに毎回ミニマルSaaS風へ逃げない。同じ作者の別プロジェクトとは別方向を選ぶ。

| 方向性 | 定義的特徴 | 向くプロダクト |
|---|---|---|
| エディトリアル/スイス | 文字が主役。大胆な見出し（clamp可変）、厳格グリッド、余白で分節 | 情報系・メディア・ポートフォリオ |
| ソフト・ネオブルータリズム | 太い境界線(2-3px)、ベタ塗り面、硬い影、角丸ほぼ無し。配色2-3色 | ツール・学習系・若年向け |
| インダストリアル/モノ | 等幅or幾何学サンセリフ、罫線区切り、高データ密度、装飾ゼロ | ダッシュボード・開発者向け・金融 |
| オーガニック/ナチュラル | アースカラー、紙/布テクスチャ(noise)、丸みと手仕事感、セリフ見出し | 健康・食・ライフスタイル |
| ラグジュアリー/端正 | 細身セリフ+広letter-spacing、濃紺/黒+金or生成りの2色、余白過剰 | 高級感・ブランドサイト |
| レトロ/クラフト | 特定年代モチーフ（活版・新聞・90sWeb等）を1つ決めて徹底 | 個性優先の企画・キャンペーン |

### 2. トークンを具体値で固定する

- **配色**: 3色まで（支配60% / 中立30% / アクセント10%）。派生は同色相の明度違いのみ。背景は純白/純黒でなく暖色or寒色に寄せる。semantic色(成功/警告/エラー)は別枠
- **フォント**: 見出し+本文のペア。欧文は Inter/Roboto/Arial/Poppins/Space Grotesk/Geist 禁止。和文は Noto Sans JP 一択にしない（Zen Kaku Gothic New / BIZ UDPGothic / Shippori Mincho / Zen Old Mincho / M PLUS Rounded 1c 等から選ぶ）
- **タイプスケール**: 1本（アプリ×1.25 / エディトリアル×1.333）。本文16px以上、行長60-80字
- **角丸・影・境界線**: 方向性ごとに1セット
- **余白**: 8ptグリッド。コンポーネント内 < コンポーネント間 < セクション間
- **モーション**: 効かせ所を1つ。全要素一律fade-inは禁止

### 3. `template.md` に従って DESIGN.md をプロジェクトルートに書く

## AI製の「指紋」ブラックリスト（DESIGN.mdにも転記する）

- 紫→青グラデーション、白背景+紫アクセント、ラベンダー
- Inter/Roboto/Poppins/Space Grotesk/Geist の見出し使い
- 中央寄せヒーロー+H1直上badge、「1·2·3」ステップ行、横並び3枚featureカード、hero→3カード→ロゴ帯→pricing→FAQ→footer の雛形直送
- 全カード1px灰色枠、色付き左ボーダー、無加工の rounded-2xl shadow-lg p-6、過剰カード化
- 理由なきダークモード既定、ネオングロー枠、意味なきglassmorphism、ヒーロー背景の3Dブロブ
- 全要素一律fade-in、巨大丸角アイコンを見出し上に置く定型、全セクションall-capsラベル
- カード区切りは「余白→背景明度3-5%差→薄い影」の順で試し、枠線は最後の手段

## 可読性ガードレール（個性より優先）

本文16px以上・行長60-80字・十分なコントラスト（WCAG AA目安）・タップ領域44px以上・階層はサイズと太さで明示。
**「個性的だが読みにくい」は不合格。** 迷ったら可読性を取る。

## 出荷前QA（UI実装後に毎回）

1. ブラックリスト照合に1つも該当しない
2. スクイントテスト: サムネイル縮小でも階層が読める
3. インタラクティブ要素の全状態（hover/focus/active/disabled/loading/empty/error）が設計済み
4. スクリーンショットを実際に見て判断する（マークアップだけで合格にしない）
