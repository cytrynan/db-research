## 編成の判断

- **委任した理由**: `features/sync` は既存の冪等 API（ingest / embed / facts / summarize）の組み合わせで入出力が有界・他モジュールとファイルが重ならない。
- **司令塔が抱えた作業**: ask の抽出（cli.py と 3 入口にまたがる・設計判断が多い）、serve（Windows の detached 起動・環境変数の順序など罠が多い）、mcp（小さい）、配線、測定。
- **却下した編成案**: serve も別の係に出す案（A4 の配布前レビューが要る・cli.py の配線で待ち合わせが増える・テスト DB の競合）。全部を自分でやる案（並行性を捨てる）。

## 受入検証係（Codex・読み取り専用・既定モデル gpt-6-astra）の実測

- **任せたタスク**: R1〜R8 の受入検証（1 巡目 2026-10-06 14:58〜15:07・約 9 分・`codex-safe.sh exec -C <scratchpad/review-daily-use>`・専用 DB `dbr_test_codex`・fake モデル・書込は result.md のみ）。
- **出来**: **必須の指摘 4 件・観察 2 件、誤指摘 0**。4 件は全部実在した（司令塔が各 1 件ずつ再現: MCP count の `v_by_bundle` → exit 2／serve の exit 1／experiments 6 件の ScannerError／count 1.08 秒）。観察の「負の Content-Length で上限回避」は司令塔が見落としていた実欠陥（ハンドラ単体で再現し、生ソケットのテストで固定）。FAIL の仕分けが丁寧で、R1・R3 は「実装側の記録に基づく未達」と自分で独立再現していない範囲を明記していた。
- **止まった点**: stdio の MCP クライアント接続が `PermissionError: [WinError 5]`（asyncio の Windows パイプ作成・サンドボックス起因）で UNVERIFIED。gate.sh は書込制限で未実行＝R7 UNVERIFIED（司令塔が代わりに実行）。PowerShell の stdin 経由で日本語が化けて count の推定に 1 回失敗（ASCII に直して再試行）。
- **具体→抽象**: 受入基準を R 番号で閉じて渡すと、Codex は「字義を満たすが目的に反する経路」まで探しに行く（指摘 1 は要件に無いビュー名入力、観察 1 は要件に無い本文長）。**司令塔が自分の測定記録（1.08 秒・6 件未取り込み）を「報告した」つもりでも、受入基準の字義に照らせば FAIL** だと検証係が言うことで、司令塔の「報告で済ませる」癖が止まる。
- **次回の割り振り判断**: 受入検証は引き続き Codex。依頼文に「司令塔の測定記録の数値も受入基準に照らして判定せよ」と明記すると、1 巡目で全部出る。stdio の MCP 接続はサンドボックスで無理なので司令塔側で確認する項目として依頼文に書く。

### readonly-reviewer（Claude Opus 5.5・役割: 受入検証 2 巡目の代行＝例外(c)）

- **任せたタスク**: 1 巡目の指摘 4 件・観察 2 件・追加変更 1 件の解消確認と回帰確認（Codex が usage limit で起動不能＝解除まで 3 時間超なので機械条件により代行）。約 27 分・294k トークン・ツール 61 回。
- **出来**: 7 点を全部「修正済」と判定し、**同梱テストが差し替えているところを実経路で測り直した**（指摘 2: `sentence_transformers` だけを壊して CLI `serve` → 実 `serve()` → 実 `LocalE5` の経路で exit 5）。新しい必須の指摘は R8 の文書不整合 1 件（FD の 0.3 秒・design の 409）と R3 の持ち越し。観察 6 件のうち 3 件は実欠陥（壊れたリクエスト行で AttributeError・メソッド名のログ・子の終了を見ない 90 秒待ち）で司令塔が回収。書き込みが無かったことを serve.log のサイズ・時刻と `git status` の行数で証明した。
- **止まった点**: Bash のヒアドキュメントで 2 回 `unexpected EOF`（本セッションで 3 者目の再現）→ PowerShell の here-string に切り替え。PowerShell ツールの安全検査が Python の `del` を Remove-Item とみなしてブロック→`pop` に書き換え。この環境では `python -c pass` に 2.2 秒かかり R3 の秒数は測れない（司令塔の測定に依拠）。
- **具体→抽象**: 2 巡目に「同梱テストが何を差し替えているか」を見る係を置くと、**テストが通ることと修正が入っていることの差**が埋まる（`serve()` 丸ごと差し替えのテストは、本物が例外を握りつぶしても気づけない）。依頼文で「コードを読んだだけで『入っている』と書かない」と縛ったのが効いた。
- **次回の割り振り判断**: Codex 不可のときの代行は Opus で十分（1 巡目の Codex と同等の網羅・誤指摘 0）。stdio MCP の接続確認のようにサンドボックスで無理な項目は、最初から Claude 側の係に振る。
