### 計画と実績の差分
**計画と異なった点**:
- HNSW の索引強制は `enable_seqscan=off` だけでは効かなかった。①`ORDER BY 距離, c.id` の同点固定列が索引の順序提供を無効にする ②JOIN 形だと小さい表で planner が chunk/document 側から結合して Sort に落ちる ③小表では別索引＋Sort を選ぶ。→ 索引用の SQL を**サブクエリで先に LIMIT する形**に分け、`enable_sort=off`・`hnsw.iterative_scan=relaxed_order` を追加。副作用として索引強制時は同点固定と bundle 絞り込みを諦めた（要件には無い）
- sweep の結果（fts 重み 0 が最良）を見て、方式 `embed_ctx`（文脈付き埋め込み単体）を find の比較に**追加**した。結果は 6 方式中**最良**（recall@5 0.90・MRR 0.811・Q06 が 1 位）。計画時点では「ハイブリッドが基準」という前提で、単体を測る発想が無かった
- bench の `--label` を最初から使い、v5 と旧 JSON の上書きを防いだ（前単位の反省）

**新たに必要になったタスク**:
- テスト DB で HNSW を使わせるための合成断片（400 行）＋`ANALYZE`。fixture 十数行では planner が索引を使わない
- カバレッジ回復のための統合テスト（sweep/hnsw/CLI を fake モデルで通す）。新モジュールを足した直後に 76% に落ちた

### 止まった点・失敗した点（**必須。1件以上**）
- **何が起きたか**: 「ゲート通過時だけ commit」の連鎖なのに、カバレッジ 76% の状態で commit が通った（3 回目の同型事故。今回は `pytest … | grep … | tail` の**パイプが pytest の exit code を隠した**）
- **原因**: `&&` は最後のコマンド（tail）の成否しか見ない。過去 2 回は「`&&` の外に commit を書いた」で、今回は「パイプで隠れた」。同じ「ゲートが gate していない」事故が形を変えて再発
- **次にどうするか**: ゲートの連鎖は `set -o pipefail` を先頭に置く（この単位の後半から適用済み）。**ゲートは1回書いたら再利用する**（毎回手で組み直すから形が変わる）→ `scripts/gate.sh` 化を次単位で
- **何が起きたか（2件目）**: `enable_seqscan=off` で索引が使われると思い込み、統合テストが 3 回落ちた
- **原因**: 「seq scan を止めれば索引に行く」という一般論。実際は他の索引＋Sort という第三の経路があり、planner はそこへ逃げる
- **次にどうするか**: 「索引を使わせる」検証は EXPLAIN の文字列を assert に入れる（今回入れていたので気づけた）。原因の切り分けは psql で単表→WHERE→JOIN と段階的に形を変えて EXPLAIN（今回これで 1 発で特定）

### 学んだこと
**技術的な学び**:
- 具体: 同点固定の `, c.id` を ORDER BY に足すと HNSW が使えない
  - 抽象: **再現性（決定的な順序）と近似索引は両立しない**。厳密検索＝再現性、索引検索＝速度、で SQL を分けるのが正しい
- 具体: 2,154 行では HNSW 強制でも厳密（7.2 ms）と同じ速さで、ef_search=40 だと上位 20 の 7% を落とす
  - 抽象: 数千行規模で近似索引を使う理由は無い。索引は「行数が増えて厳密検索が遅くなったら」入れる
- 具体: RRF の fts 重みを 0→1 に振ると MRR 0.811→0.676 と単調に下がった
  - 抽象: 「ハイブリッド＞単体」は前提にできない。片側が弱いと融合は単体に負ける。**融合を採用する前に重み 0 のセルを必ず測る**
- 具体: 並べ直しは Q08 を 13→4 位に上げたが Q02 を 1→5 位、Q06 を 10→18 位に下げた
  - 抽象: cross-encoder は断片単位で採点するので、文書の「代表断片」が入れ替わって文書順位が動く。文書単位で評価するなら断片スコアの集約（max/平均）も設計変数

**プロセス上の改善点**:
- 測定 → 数字を見て方式を追加（embed_ctx）→ 再測定、の往復を同じ作業単位で回せた。bench が 5 分で回るのが効いている
- 実データ測定をバックグラウンドにして、その間にテスト・知見記録を進めた（CPU 競合はあるが壁時計は短い）

**リポジトリをまたいで使える知見**:
