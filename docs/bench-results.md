## 読み方（この 10 問・この規模での観察。一般化しない）
- **文脈付与は効いた**: MRR 0.539（embed）→ 0.676（hybrid_ctx）。Q01/Q02（「何を飲んでるんだっけ」「度数どこ」）が 4位・2位 → 1位。Anthropic の Contextual Retrieval と同じ方向
- **全文検索は単体では弱い**: 言い換え質問（Q06「目が悪くなってきた」→ 視力・メガネ、Q08「スキャナ的なこと」→ OCR）は語が一致せず未ヒット。埋め込みはこれを拾う
- **RRF の効き目は候補数に敏感**: 各系 100 件（v3）では hybrid が embed 単体より recall@5 で劣った（0.70 vs 0.80）が、500 件（v4）では同等（0.80）・MRR は上（0.552 vs 0.539）。ただし recall@20 は 0.90（Q06 が 20 位圏外）で embed（1.00）に負ける。等重み RRF は fts の弱い一致を持ち込むので、次単位で重み／候補数を掃引する
- Q06・Q08 は全方式で弱い＝**言い換えの語彙差**。並べ直し（cross-encoder）で改善するかが次の測定点

## 測定中に見つけた方法論の欠陥（v1→v3 の経緯・一次記録は JSON 2 本）
| 版 | 何を変えたか | fts recall@5 | embed | hybrid_ctx MRR |
|---|---|---|---|---|
| v1 | `plainto_tsquery`（全語 AND）＋機能語も索引 | 0.20（未ヒット 8） | 0.80 | 0.794 |
| v2 | 語を OR で結合＋助詞・助動詞・記号を索引から除外 | 0.40 | 0.80 | 0.708 ※ |
| v3 | ベクトル検索の同点を `c.id` で固定 | 0.40 | 0.80 | 0.675 |
| v4 | 断片の打ち切り 100→500・hybrid の一次取得を各系 500 件に（受入検証の欠陥1）**＝確定値** | 0.40 | 0.80 | 0.676 |

※ v2 の JSON は同日再実行で上書きされ**残っていない**（コンソール表の写し。受入検証の指摘）。v1 と v3 は JSON あり。

1. **AND クエリ**: 日本語の質問は助詞が必ず入るので、全語 AND では該当断片がほぼ無くなる（10 問中 8 問がヒット 0）。方式の欠陥であって「fts が弱い」ではない。修正後も fts 単体は 0.40 で、これが実力
2. **同点の揺れ**: v1→v2 で embed の順位が変わった（Q06 17→未ヒット）。原因は同一本文の断片（＝同一ベクトル）の同点順が `UPDATE chunk` 後のヒープ順に依存していたため。`ORDER BY 距離, c.id` で固定し、以後 2 回実行で JSON 一致
3. **HNSW は使われていない**: `EXPLAIN` で Seq Scan（厳密計算）。約 2,000 行では planner が索引を選ばない。したがって本測定の `ef_search=40` は無効で、ef_search の比較実験は `SET LOCAL enable_seqscan = off` で索引を強制してから行う（未実施）
5. **断片の打ち切り**（v3→v4）: 上位 100 断片を文書に畳むと 20 文書に届かず、11〜20 位が消えることがあった（hybrid の Q08 が「未ヒット」→ 14 位）。bench は断片を 500 件取り、hybrid の一次取得も各系 500 件にした。候補数が増えた分 RRF の結果も動く（上の「候補数に敏感」）
4. hybrid_ctx の MRR が v1（0.794）より v3/v4（0.675/0.676）で低いのは、v1 の fts が「ほぼ空」だったため RRF が実質 embed 単体＝雑音が無かったから。**fts を直したら融合が悪化した**という逆説。等重み RRF の限界として記録

## 次の測定点（次単位）

- **この 10 問の最良は embed_ctx（文脈付き埋め込み単体）**: recall@5 0.90・MRR 0.811。言い換え質問 Q06（「目が悪くなってきた」）が **1 位**、Q08 が 9 位。sweep の w_fts=0 と同値（同じ計算）。
- **並べ直しは hybrid_ctx を改善した**（MRR 0.676→0.751、recall@5 0.80→0.90）が、embed_ctx 単体（0.811）には届かない。並べ直しの土台が「fts で汚れた融合」だったため。言い換え質問 Q08（「スキャナ的なこと」→OCR）が 13 位→**4 位**、Q05 が 4→1 位。
- **ただし万能ではない**: Q02（「度数どこ」）が 1→5 位、Q06（「目が悪くなってきた」）が 10→18 位に**下がった**。cross-encoder が短い質問と長い断片の組で別の断片を上げたと見られる（断片単位のスコアなので、文書の代表断片が入れ替わる）。

- **この 10 問では、全文検索を混ぜるほど MRR が下がる**（w_fts 0→1 で 0.811→0.676）。最良は **fts 重み 0＝文脈付き埋め込み単体（MRR 0.811）**で、並べ直し（0.751）より上。
- 解釈: fts の OR 検索が持ち込む弱い一致が RRF で割り込む。fts が勝つ質問（Q01/Q09 で 1 位）は埋め込みでも上位なので、融合の利得が出ない。**「ハイブリッドが常に良い」は成り立たない**（データと質問に依存）。
- 次の測定点: 並べ直しを embed_ctx 単体の上に載せる（`embed_ctx_rerank`）／語彙一致が効く質問（型番・固有名詞）を質問セットに足す。

- 強制時の `EXPLAIN` は `Index Scan using chunk_embedding_hnsw`（JSON `index_used_when_forced: true`）。
- **2,154 行では索引の速度メリットは無い**（厳密 7.2 ms と同等）。一方 ef_search=40 は上位 20 の 7% を取りこぼす。**この規模では厳密検索（索引なし）が正解**で、索引は行数が増えてから。
